    3. Set headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no`.

    7. Start heartbeat ticker (15s) per DESIGN.md Section 7.

    11. On heartbeat: write SSE comment `: heartbeat\n\n`, flush.
    12. On ctx.Done(): return.
    SSE write format: `fmt.Fprintf(c.Writer, "event: update\ndata: %s\n\n", jsonPayload)` followed by `flusher.Flush()` — match DESIGN.md Section 7 exactly.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSE client → GET /queue/status | Untrusted ticketId path param — could be an arbitrary string |
| scheduler goroutine → Redis | Internal; scheduler operates on Redis directly — leader lock prevents race |
| pub/sub payload → SSE handler | Scheduler-produced JSON; consumed by SSE handler — internal trust boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | GET /queue/status/:ticketId — ticketId path param | medium | mitigate | Validate that ticketId exists in Redis (EventIDFromTicket returns 404 if not found). An unknown ticketId returns 404, not a position. |
| T-02-02 | Denial of Service | SSE connections — one goroutine + one Redis subscription per SSE client | medium | accept | SSE is restricted to near-front users (rank < 200) via upgrade_to_sse hint on poll — total concurrent SSE connections bounded by threshold × active events, not total queue depth. Per DESIGN.md Section 7. |
| T-02-03 | Tampering | scheduler:lock:{eventId} — Redis SETNX NX+TTL | low | mitigate | Lock has 10-second TTL — expired lock auto-releases, preventing permanent lock starvation. Lock key uses NX (Set if Not eXists) atomically. |
| T-02-04 | Information Disclosure | pub/sub payload contains admission JWT | medium | mitigate | Pub/sub channel `ticket:updates:{ticketId}` is namespaced per-ticket (UUID). An attacker would need to know the ticketId to subscribe. Phase 1 has no auth on Redis — acceptable for local dev. Production: add Redis AUTH or TLS (Phase 3). |
| T-02-05 | Denial of Service | scheduler admitBatch flooding active:{eventId} | low | accept | D-06: no ceiling enforcement in Phase 1. active counter can exceed capacity in Phase 1 — by design. Phase 2 adds headroom check. |
| T-02-SC | Tampering | Scheduler goroutine context leak — goroutine not stopped on server shutdown | medium | mitigate | scheduler.Start() uses ctx parameter from signal.NotifyContext — SIGTERM/SIGINT cancels context and stops scheduler loop cleanly. |
