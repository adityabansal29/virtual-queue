    ## internal/api/handler_join.go
    Package `api`. Define `Handler` struct with fields `cfg config.Config` and `rdb *redis.Client`. Define `NewHandler(cfg config.Config, rdb *redis.Client) *Handler`.

    Define `func (h *Handler) Join(c *gin.Context)`:
    1. Parse request body JSON: struct with optional `EventID string json:"eventId"`. If EventID is empty, use `h.cfg.DefaultEventID`.
    2. Generate ticketId: `uuid.New().String()`.
    3. Score: `time.Now().UnixMilli()` as float64.
    4. Call `h.rdb.ZAdd(ctx, "queue:"+eventID, redis.Z{Score: score, Member: ticketId})` — idempotency note: if the same ticketId is re-submitted (browser retry), ZADD NX flag prevents overwriting the original score, preserving FIFO order. Use `redis.Z{Score: score, Member: ticketId}` without NX for simplicity in Phase 1 (ponytail: add ZAddArgs with NX when idempotent re-joins are required).
    5. Call `h.rdb.HSet(ctx, "ticket:"+ticketId, "ticketId", ticketId, "eventId", eventID, "joinTime", score)`.
    6. Respond: `c.JSON(http.StatusOK, gin.H{"ticketId": ticketId, "eventId": eventID, "position": "queued"})`.
    Error handling: if ZAdd fails, log with slog and return HTTP 503 `{"error": "queue unavailable"}`.

    Boundary edge (QUEUE-01 probe): If ZADD is called with a duplicate ticketId (same member already in the set), Redis updates the score. In Phase 1 this is acceptable since ticketIds are UUIDs and duplicates are practically impossible. Document with comment: `// ponytail: ZADD without NX — UUID collision probability ~0; add ZAddArgs{NX:true} if idempotent rejoin semantics are required`.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | POST /queue/join — eventId field | low | accept | Phase 1 uses a single hard-coded DefaultEventID; eventId from body is accepted but defaults are safe. Phase 2 will add event validation against a config store. |
| T-01-02 | Tampering | Redis sorted set queue:{eventId} | medium | mitigate | Redis is bound to Docker internal network (not exposed on 0.0.0.0 to host unless docker-compose ports mapping is present — use 127.0.0.1:6379:6379 binding). |
| T-01-03 | Information Disclosure | .env file containing ADMISSION_SECRET/SESSION_SECRET | high | mitigate | .env added to .gitignore. .env.example committed with placeholder values only. Startup panics if secrets are empty or identical (config.Load() guard). |
| T-01-04 | Denial of Service | POST /queue/join flood — Redis ZADD O(log N) per call | medium | accept | No rate limiting in Phase 1 (ponytail: add per-IP rate limit middleware when BOT-01 CAPTCHA is implemented). Acceptable for local dev stack. |
| T-01-05 | Elevation of Privilege | Secrets leaked via startup log | low | mitigate | config.Load() asserts secrets are non-empty but MUST NOT log secret values — only log "admission_secret=set" boolean. slog usage in main.go must not include cfg.AdmissionSecret or cfg.SessionSecret in log fields. |
| T-01-SC | Tampering | go get install of gin/go-redis/jwt packages | high | mitigate | All three packages verified against pkg.go.dev before use (see task action). go.sum provides content-addressable integrity for all transitive deps. No [ASSUMED] or [SUS] packages. |
